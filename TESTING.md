## BUG-01

- Заголовок: POST с `topic: "api"` возвращает 201 и id, но заявка не сохраняется: GET по id → 404, в списке её нет
- Требование: R7 (успешный POST создаёт запись, последующие GET возвращают её)
- Версия/режим/окружение: workshop-1.0, commit 4e8c3c2, режим normal, API-лаборатория / curl, Opera GX 136
- Предусловия и точные данные: выполнен сброс стенда, 3 заявки. Тело запроса: `{"name": "Игорь", "email": "igor@example.com", "topic": "api"}`
- Шаги воспроизведения:
  1. `GET /applications` → 200, в массиве 3 объекта (id 1, 2, 3).
  2. `POST /applications` с телом выше, `Content-Type: application/json`.
  3. Из ответа записать `id`.
  4. `GET /applications/<id из шага 3>`.
  5. `GET /applications`.
- Ожидаемый результат: шаг 2 → `201` с новым id; шаг 4 → `200` и тот же объект; шаг 5 → 4 объекта, включая «Игорь».
- Фактический результат: шаг 2 → `201 Created`, `"id": "4"`, `"topic": "api"`; шаг 4 → `404`, `"code": "NOT_FOUND"`; шаг 5 → по-прежнему 3 объекта (Анна, Михаил, София). Контроль: тот же POST с `"topic": "html"` → 201, id 5, `GET /applications/5` → 200, то есть дефект проявляется только для темы `api`. В UI: отправка «Игорь / igor@example.com / HTTP и API» показывает «Заявка #4 сохранена. Спасибо!», после F5 карточки «Игорь» нет.
- Свидетельство: ответы POST/GET выше (заголовки `X-Lab-Version: workshop-1.0`, `X-Lab-Mode: normal`); `evidence/bug01_api_topic_after_reload.png`
- Влияние на пользователя: каждый, кто выбирает направление «HTTP и API», видит подтверждение, но его заявка теряется. Целое направление мастерской не получает участников, а пользователь об этом не узнаёт.
- Предложенный приоритет и обоснование: Critical. Тихая потеря данных и ложный успех на основном сценарии; блокирует выпуск.
- Гипотеза причины, если есть: `backend/server.mjs`, `createApplication`: `if (application.topic !== 'api') database.applications.push(application);` - запись с темой api не добавляется в базу, но ответ формируется.

## Решение о выпуске

Продукт **не готов** к открытию записи. Основной сценарий для тем «HTML и CSS» и «JavaScript и DOM» работает: заявка сохраняется, переживает перезапуск сервера, неверный email и неизвестная тема отклоняются. Но заявки на направление «HTTP и API» теряются при ложном подтверждении (BUG-01, Critical), а список участников показывает дубли (BUG-03) и неверную тему для JavaScript (BUG-07). Потеря данных при ошибке (BUG-02) исправлена и проверена повторно; BUG-03…BUG-08 остаются открытыми. Не проверено: другие браузеры (Firefox, Safari), реальные мобильные устройства, экранные читалки, одновременная работа нескольких пользователей, независимое воспроизведение напарником.
